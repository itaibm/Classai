# Design: Curriculum-first Class Library

**Owner:** Itai · **Executor:** Claude Code · **Date:** 2026-07-04
**Governing docs:** `SCHOOL-CHARTER.md`, `docs/PRD-curriculum-player.md`, `curriculum/LESSON-FILE-SPEC.md`

## 1. Problem & POV

The Class Library today makes a parent hand-build years → subjects → classes and then AI-generates a
throwaway syllabus. That buries the real asset: `curriculum/` already describes **1085 planned lessons**
across Years 1–6 and every subject, in uniform scope files (`<subject>-year-N.md`), of which only 54 are
authored as playable `classai-lesson/1` JSON.

**New POV:** the real curriculum **is** the library. Show every planned lesson (even unprepared ones).
Authored lessons play as-is; unprepared lessons are generated by AI from the scope outline + knowledge
base on first start, then **saved to disk** so the curriculum fills itself in. Retire the manual
builder/syllabus flow.

Decisions (locked with owner): (1) replace the legacy flow fully, keep the enrollment/progress data layer
hidden underneath; (2) generated lessons are written as real `classai-lesson/1` files on disk; (3) a
learner is assigned a subject-year and can start any lesson in order; generate on start (~20–60s
"Preparing…" once, instant thereafter).

## 2. Knowledge base on disk (verified)

- `curriculum/year-N/<subject>/<subject>-year-N.md` — **scope file** (143 total). Uniform structure:
  `## Unit N — Title`, `**Essential question:**`, `**Key vocabulary:**`, then repeated
  `### Lesson N — Title` blocks each with `- **Duration:**`, `- **Objective:**`, `- **Hook:**`,
  `- **Key activity:**`, `- **Check for understanding:**`, `- **Differentiation:**` (support / stretch),
  `- **Materials:**`, `- **Joy:**`, and a unit `**End-of-unit check:**`. Lesson numbers run continuously
  across a subject-year's units.
- `curriculum/year-N/<subject>/lessons/lesson-NN-slug.json` — authored `classai-lesson/1` (54 total).
- `knowledge-base/subjects/<subject>/*.md` — deeper teaching knowledge the generator grounds in.

## 3. Architecture

Four server units + two rebuilt client screens. Each has one job and a clear interface.

### 3.1 Scope parser — `server/src/services/curriculum-scope.ts`
`parseScopeFile(markdown): ParsedScope` → `{ yearOverview, units: ParsedUnit[] }`, where a unit is
`{ number, title, essentialQuestion, keyVocabulary[], endOfUnitCheck, lessons: LessonOutline[] }` and a
`LessonOutline` is `{ lessonNumber, title, durationMin, objective, hook, keyActivity, check,
differentiation:{support,stretch}, materials, joy }`. Pure, no I/O. Field regex tolerates
`**Field:**` (colon inside bold). Missing fields default to `''`; a lesson needs only a `### Lesson N —`
heading to exist.

### 3.2 Catalog builder — `server/src/services/curriculum-catalog.ts`
`buildCatalog(): CatalogYear[]` walks `curriculum/year-N/<subject>/`:
- Parse the scope file → outlines (the planned lessons).
- Reuse the existing curriculum JSON scan → authored lessons.
- Merge by key `year/folderSubject/lessonNumber`: each catalog lesson gets `status: 'authored' | 'outline'`.
- Catalog lesson id = the authored file's id when authored, else synthesized `y{year}-{subject}-u{unit}-l{NN}`
  (matches the authored convention, e.g. `y2-maths-u1-l01`).
- Shape: `CatalogYear{ year, subjects: CatalogSubject{ subject, subjectKey, subjectLabel, yearOverview,
  units: CatalogUnit{ number, title, essentialQuestion, lessons: CatalogLesson[] } } }`.
  `CatalogLesson{ id, lessonNumber, unitNumber, title, objective, durationMin, status, deliveryMode?,
  outline }`.
- `getCatalogLesson(id)` returns `{ authored?: LessonFull, outline?: LessonOutline, meta }` for the start flow.
- `GET /api/catalog` (whole tree, summaries), `GET /api/catalog/lessons/:id` (detail incl. outline).

### 3.3 Lesson generator — `server/src/services/lesson-generator.ts`
`generateAndSaveLesson(meta, outline, unitCtx): Promise<LessonFull>`:
- Prompt (new, in `ai/prompts.ts`) grounds the LLM in the outline (objective/hook/key activity/check/
  differentiation/materials/joy), unit context (essential question, vocabulary, year overview), a slice of
  the subject `knowledge-base/subjects/*`, and the authoring rules from `LESSON-FILE-SPEC.md`. It must
  return a full `classai-lesson/1` (beats with delivery/scripts/blocks, ≥9-item practice bank with
  wrong-answers + reteach, adaptivity, delivery mode, optional video).
- Validate tolerantly with `DiskLessonSchema` (reuse). On success, set `id` = catalog id and **write**
  `curriculum/year-N/<subject>/lessons/lesson-NN-slug.json` atomically (tmp + rename).
- **Never a broken lesson:** if the big generation fails validation twice, synthesize a minimal-but-valid
  `classai-lesson/1` from the outline alone (beats from hook/key-activity/check; a 3-item practice bank
  derived from the check) and save that. Log which path was taken.
- Bring-your-own-key respected; the generator uses the connected brain via `getBrain()`.

### 3.4 Start & assignment — routes + `services/curriculum-enroll.ts`
- `ensureCurriculumClass(year, subjectFolder): ClassDefinition` — deterministic `SchoolYear` (`cur-year-N`)
  and `ClassDefinition` (`cur:y{N}-{subject}`), created on demand, `subjectKey = curriculumSubjectKey(...)`.
- `POST /api/catalog/assign { kidId, year, subject }` → ensure class + enrollment.
- `POST /api/catalog/lessons/:id/start { kidId }` → resolve authored (or generate+save) → ensure class +
  enrollment for that subject-year → `startSession` (authored director plays it). Returns `{ sessionId }`.
- `GET /api/kids/:id/curriculum` → the kid's assigned subject-years, each with the catalog units/lessons and
  per-lesson completion (a lesson is "done" if a session exists with that `curriculumId`).

### 3.5 Data layer (kept, hidden)
Reuse `classes` / `enrollments` / `sessions` / `learner_models`. A subject-year maps to one shared
auto-created class; assignment = enrollment; mastery stays keyed by lesson `topic`. No schema migration.

### 3.6 Client — rebuilt
- **Parent library** (`screens/ClassLibrary.tsx`, rebuilt): Year 1–6 tabs → subject cards → subject view
  with unit accordions → lesson rows (number, title, objective, duration, status badge ✓ Ready / ✨ AI-built,
  delivery badge). Per subject-year: "Assign to a learner" (multi-select kids). No add-year/add-class/
  syllabus UI.
- **Learner home** (`screens/LearnHome.tsx`, rebuilt): the kid's assigned subject-years as cards → open to
  units/lessons in order with progress; "Continue" starts the next unstarted lesson; any lesson startable.
  Authored plays instantly; outline lessons start into a "Preparing your lesson…" state while generation
  runs, then the classroom opens.
- The old manual `ClassDetail` / `LessonEditor` routes remain in the codebase (auto-created curriculum
  classes still render there for enrolled-kid management) but are removed from the primary navigation. This
  is a flow replacement, not a file purge — it keeps routes stable while making curriculum the default.

## 4. Data flow (start an outline-only lesson)

learner home → `POST /api/catalog/lessons/y3-history-u1-l01/start {kidId}` → catalog resolves status
`outline` → generator builds + validates + writes `lessons/lesson-01-…json` → `getCurriculumLesson` loads
it → ensure class+enrollment → `startSession` → classroom runs the authored director. Next time the same id
resolves `authored` and skips generation.

## 5. Error handling

- Malformed scope file → that subject-year is skipped in the catalog with a warning (never a crash).
- Generation failure → minimal-but-valid fallback lesson, logged; the learner still gets a lesson.
- No brain connected → start returns a clear error the UI surfaces ("Connect your brain to build this lesson").
- Disk write failure → fall back to playing the in-memory generated lesson for this session (still works),
  logged; ret/save retried next start.

## 6. Testing

- `curriculum-scope.test.ts` — parse `year-2/maths` + a thin subject; assert unit/lesson counts, fields.
- `curriculum-catalog.test.ts` — merge marks lesson-01 `authored`, an unbuilt lesson `outline`; id scheme.
- `lesson-generator.test.ts` — mock brain returns a valid `classai-lesson/1`; assert a file is written and
  re-reads/validates; assert the fallback path yields a valid lesson when the brain returns junk.
- `npm run typecheck` + `npm run build` green.

## 7. Non-goals

Authoring/editing curriculum lessons in-app; pre-generating all 1085 lessons; multi-user/cloud; changing the
bring-your-own-key or privacy model; touching the P0 authored-director internals (reused as-is).
