# Topic content contract (every subject file follows this)

Each **year file** (`year-N.md`) is a sequence of TOPICS. Every topic is written in the block below so the Classai lesson designer can read the four analysis fields plus ready-made checks directly. Keep prose tight and concrete; this is teaching material, not an essay.

---

## [Topic number]. [Topic title]

**Year / Key Stage:** Year N (ages X–Y) · **Est. minutes:** NN · **Subject strand:** (e.g. Number – fractions)

**Prerequisites:** comma-separated prior topic titles (or "none").

### Key concepts
- The 2–4 ideas the child must walk away with. One line each, plain language.

### Prior knowledge assumed
- What this lesson takes for granted the child can already do.

### Teach it (the explanation)
A concise, correct explanation written as you would say it to a 5–11 year old. Include the core model/representation (number line, part-whole, place-value, story, diagram). Use a concrete → pictorial → abstract progression where relevant.

**Worked example.** One fully worked example, step by step (these map to a `steps` block).

### Hooks (real-world angles)
- 2–3 concrete, child-friendly hooks the tutor can adapt to the learner's interests (sport, animals, games, food…).

### Misconceptions (wrong answer → why → fix)
- **Wrong answer / idea:** what the child says or does.
  **Why:** the faulty mental model behind it.
  **Fix:** the specific teaching move that corrects it.
- (1–3 of these. These feed `wrongAnswers` in the app's checks.)

### Checks (ready-to-use)
- **Q:** a question that reveals understanding. **A:** the expected answer (with brief reasoning).
- (2–4 checks of increasing difficulty. Map to `BeatCheck`.)

### Activity / practice
A short "you do" task the child completes — ideally expressible as a Classai interactive block (multipleChoice, numberEntry, ordering, matchPairs, fillBlank, categorize, speak…).

### Resources
- **Platform — exact title/topic** (what it covers). Stable, free, real. No invented video IDs.

---

> Writers: prefer breadth of *topics* with solid depth over exhaustively long single topics. Aim ~6–12 topics per year file. Always fill all four analysis fields (key concepts, prior knowledge, hooks, misconceptions) — those are what the app needs most.
